Guide

How Cents is laid out, what each area does, and how the app is put together.

Workspace layout

  • Left sidebar — navigation between the app sections. Collapse it with the chevron in its header.
  • Page area — the section you selected. It takes whatever width the sidebar and chat panel leave, so widening the chat shrinks the page.
  • Chat panel — always available on the right. Collapse it with the chevron in its header; reopen it from the vertical Chat rail.
  • Resizing — drag the vertical dividers to resize the sidebar, the chat panel and the conversation history. Handles are keyboard accessible with the left and right arrow keys.
  • Persistence — every collapse state and panel width is stored in your browser, so the layout is the same after a reload.

Sections

  • Guide — this page. It is the landing view after you sign in.
  • Documents — upload files and review everything that has been ingested.
  • Tools — tools the assistant may call during a conversation. Not available yet.
  • Agents — agent definitions that combine a model, tools and instructions. Not available yet.
  • Knowledge Base — the indexed content answers are retrieved from. Not available yet.
  • Configuration — workspace settings, models and integrations. Not available yet.
  • Metrics — usage, latency and cost. Not available yet.

Chatting

  1. Open the chat panel on the right.
  2. Press History to show past conversations, then pick one, or press New to start a fresh conversation.
  3. Type a message and press Enter. The assistant reply streams in as it is generated.
  4. Conversations can be renamed or deleted from the history list.

Architecture

  • Angular standalone components with signals for state; there are no NgModules.
  • Shell — NavShellComponent wraps the router outlet and hosts the sidebar, page area and chat panel. LayoutService owns collapse and width state, persisted to localStorage under cents.layout.*. ResizeHandleDirective implements the horizontal drag handles.
  • Auth — AuthService holds the JWT in memory, authInterceptor attaches it to requests and signs you out on a 401, and authGuard protects every route except login and register.
  • Chat — ConversationService manages the conversation list and the active conversation; ChatService sends messages and consumes the streamed response.
  • Documents — DocumentService handles uploads and listing.
  • Backend — all calls go to API_BASE_URL, taken from the environment files in src/environments.

Keeping this page accurate

This guide is part of the app, not external documentation. Whenever a feature, section or architectural decision changes, update this page in the same change so it always describes the current behaviour.
